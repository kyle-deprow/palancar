# Palancar code audit — 2026-08-22

Scope: full source audit at HEAD `7d2d9d6` (handoff commit on `47aa5b3`) covering
`apps/relay`, `apps/g2-client`, all `packages/*`, `tools/*`, `infra/modules`,
`infra/environments/dev`, and committed `infra/scripts`. Four independent
reviewers, findings verified against actual source. Workspace gates rerun at
audit time: lint, typecheck, build, and full test suite all pass; Terraform
validates on the pinned 1.15.8 binary (PATH default is 1.15.6).

## Verdict

The implementation is in good shape where it matters: fail-closed behavior is
real (no memory-state fallback in deployed mode, no fail-open branch in the
language gate or generated-output validation), the resampler/commit-cadence
math in the Azure transcription adapter is correct, cancellation propagates
end-to-end, ETag/CAS handling in security-state reconciles ambiguous outcomes,
and no LiteLLM/OpenRouter runtime path remains (only deliberate env-var
rejection guards, one stale telemetry allow-list entry, and gitignored stale
`dist/` artifacts). None of the findings below block the handoff critical path
(image promotion → smoke tests → credential cleanup).

Two systemic non-blocking issues: (1) a pervasive "hostile same-process
caller" defensive style — proxy detection, prototype walking, descriptor
re-validation of objects the code itself constructs — duplicated in 4+ parallel
implementations across relay, client, and packages, accounting for very roughly
1.5–2k lines; (2) `infra/scripts` is ~57k lines of hand-rolled ceremony
guarding ~3.3k lines of Terraform, much of it machine-bound via hard-coded
`/home/dev/...` paths, with several thousand lines of superseded historical
guard modes.

## Real defects (fix in a post-promotion slice)

### G2 client (ships via .ehpk, not the relay image)

- **HIGH — all non-recovery transport errors escalate to terminal "Restart
  app"**: `apps/g2-client/src/bridge/runtime.ts:1888-1905` maps every
  `RelayTransportError` to fatal, ignoring `kind`/`recoveryDisposition`.
  Client-side audio queue overflow on a long utterance
  (`src/transport/index.ts:729-731`) bricks the app while the equivalent
  server-side abort transitions gracefully to Ready.
- **HIGH — server flow-control `pause` aborts within one audio frame**:
  `transport/index.ts:1149` sets paused, but `pushPcm`
  (`transport/index.ts:723-726`) aborts on the next chunk; the runtime never
  gates the mic on pause. `flowState:"abort"` (a protocol-legal server
  response) likewise escalates to fatal via the finding above.
- **MEDIUM — no client watchdog in Finalizing/Translating**: after commit the
  client waits indefinitely for final/translation events; press is a no-op in
  those states (`src/state/index.ts:1515-1598`).
- **LOW/MEDIUM — `eventType === undefined` synthesizes a press**
  (`runtime.ts:1621`); in Ready/Results that starts a live microphone turn.
- **LOW — duplicate `session.ready` kills the session**
  (`transport/index.ts:1361-1375`) where the reducer would treat it as
  idempotent.

### Relay (would require a new image — do NOT fold into the pending promotion)

- **Wrong close semantics + false telemetry on host-level frame rejection**:
  `apps/relay/src/host.ts:2761-2781` maps every acceptor rejection (including
  `utterance-limit`) to `4503 provider_unavailable` + a `state_store.failure`
  metric; the core's correct `4408 duration_limit` path
  (`src/session.ts:895-926`) is unreachable in the composed host.
- **Partial-transcript delta joining inserts spurious whitespace**:
  `packages/transcription/src/azure-adapter.ts:1367` unconditionally
  space-joins deltas and `normalizeText` never collapses interior runs —
  sub-word deltas render as `"trans lation"` in live partials. Finals are
  unaffected. (Verified in source directly.)
- **Unbounded per-process growth**: `host.ts:2187-2188` —
  `revokedInstallations` / `minimumCredentialVersions` only cleared at
  `stop()`.
- **Zero-progress loop hazard in grant metering**: `host.ts:2763-2777` — a
  grant with `remainingOriginalSamples === 0` re-reserves forever; cheap guard.
- **Generation dedup wedge on hostile options**: `packages/generation/src/service.ts:590-619`
  re-reads `options.signal` after inserting into `#completionPromises`; a
  throwing second read leaves a never-settling entry keyed forever.
- **Deduped completions share one abort controller**: `service.ts:629-643` —
  one caller's abort rejects all callers on the same turn; if intended,
  comment it.
- **Deployment-name regex disagreement**: `azure-adapter.ts:58` /
  `azure-client.ts:12` reject valid 2-character deployment names that
  `azure-server.ts:36` accepts.

### security-state / expiry cleanup

- **Cleanup pagination cursor lost every run → tail starvation**:
  `packages/security-state/src/azure-store.ts:1292-1294` keeps the
  continuation token in instance memory; the daily job
  (`tools/expiry-cleanup/src/index.ts:281`) makes one 1000-row call from a
  fresh container. >1000 security rows means the rate table (30-day retention)
  is never scanned. Persist the token or loop to exhaustion.
- **Backwards wall-clock step becomes an outage**: `azure-store.ts:1320-1325`,
  `store.ts:521-530` — every op fails `state-unavailable` until `Date.now()`
  re-passes the high-water mark; no slack tolerance.
- **CAS exhaustion misreported as `invalid-ticket`** (`azure-store.ts:2628`,
  `:2765`) — contention surfaces as a credential-class 4xx instead of
  `state-unavailable`.
- **Mock/durable drift**: generation `authorizationId` identity omits
  `credentialVersion`/`decision` in the memory store
  (`store.ts:1444-1448` vs `azure-store.ts:3192-3203`); rate-limit rejections
  collapse to `invalid-ticket` in memory vs `quota-exceeded` durable.
- **Readiness check is a durable CAS write** (`azure-store.ts:3608-3651`) —
  masked only by `maxReplicas = 1`; flaps under any concurrency.
- **`reserveAudio` post-commit handoff failure leaks the reservation** until
  grant TTL (1s) — minor, fail-closed.

## Worthwhile cleanups (batched, no architecture changes)

- **Dead code, ~500+ lines in the client alone**: unused
  `src/display/scheduler.ts` (224) + `validator.ts` (75) (runtime has its own
  debounce); dead `request-translation`/`request-suggestions` effects; dead
  exports/aliases (`G2RelayTransport`, triple WebSocket option aliases,
  `MAX_DISPLAY_MESSAGE_LENGTH`, 7 of 8 `PAGE_LAYOUTS`).
- **Dead code elsewhere**: `packages/transcription/src/evidence.ts` (~300
  lines, no non-test consumer); `azure-client.ts:198-217` append builder;
  relay `dev-auth.ts` (legacy, one test); many alias exports across
  contracts/telemetry/security-state/generation/language-registry (verified
  unused by repo-wide grep); dead relay exports
  (`createTestTicketClaim`, `DEVELOPMENT_PROVISIONAL_CLASSIFIER_ID`, legacy
  classifier aliases, `defaultGenerationService` dead fixture config).
- **Duplication to consolidate**: `isPlainObject` defined 8+ times; four
  parallel proxy-safe reflection helper implementations in the relay; App
  Insights connection-string validation implemented twice
  (`host.ts:539-597` vs `telemetry.ts:316-396`); ~1,150 lines of mechanical
  entity serialization pairs in `azure-store.ts` derivable from a field-spec
  table; duplicated constants/regexes between the two security stores;
  bounded-JSON readers and clone/freeze helpers duplicated in the client.
- **Hot-path waste**: double decode + double acceptor bookkeeping + two buffer
  copies per audio frame between relay host and core (`host.ts:2756` vs
  `session.ts:872-883`), and double JSON parse/assert on control messages;
  client reducer performs ~4 recursive clone/freeze passes per
  `transcript.partial`; per-byte `String.fromCharCode`+`btoa` base64 on 4.8 KB
  chunks 10×/s (`azure-adapter.ts:1583-1587`) — use `Buffer`.
- **Stale remnants**: `packages/telemetry/src/index.ts:679` still registers
  `litellm-chat` in `EXPORT_PROVIDER_VERSIONS`; `packages/generation/dist/`
  still contains `litellm.js`/`litellm.d.ts` (gitignored; add a clean step or
  clean build); `apps/litellm-proxy/` is an empty untracked directory — rmdir.
- **Two-language hardcoding in client display**: `runtime.ts:286`, `:443`
  bypass the language registry ("Spanish / Turkish" literals).
- **infra/scripts proportionality**: archive superseded guard modes in
  `assert-dev-plan.mjs` (and their fixtures) once cleanup completes; the plan
  guard emits only "plan guard rejected plan" with zero diagnostics — the
  dominant maintainability cost; hard-coded `/home/dev/...` and `/usr/bin/az`
  paths make all committed scripts machine-bound;
  `verify-acr-image-platform.mjs:469` asserts `accessToken === refreshToken`
  (incidental az behavior); `remove-env-entry.mjs` is 4k lines to delete one
  env line.
- **Terraform**: five near-identical latency alert blocks in
  `infra/modules/observability/monitoring.tf:44-215`; ARM-ID regexes
  duplicated ~28× across module variables.

## Explicitly verified non-issues

- No fail-open memory fallback in deployed mode (hard-fenced to
  `LOCAL_MOCK_ONLY` + localhost + mock providers).
- Resampler/commit cadence exact; finalize covers the one-sample lag; reset on
  every cleanup path.
- Socket/timer/listener lifecycle clean on all terminal paths traced.
- Language gate and generated-output validation fail closed on every
  unmatched branch.
- Rate-window rows capped; telemetry sink and OTLP queue bounded; OData
  quote-escaping correct; SDK retries correctly disabled in favor of CAS loop.
